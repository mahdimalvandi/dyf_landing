# اجرای اتصال واقعی فرانت و بک

## اجرای محلی

```bash
cd backend
cp .env.example .env
go run ./cmd/migrate up
go run ./cmd/server
```

در ترمینال دیگر:

```bash
cd frontend
npm ci
npm run dev
```

پنل: http://localhost:5173/admin

در محیط محلی VITE_API_BASE_URL خالی است و Vite مسیرهای /api و /uploads را به 8080 پروکسی می‌کند. در production همین مسیرها باید در reverse proxy تنظیم شوند؛ در صورت دامنه جدا VITE_API_BASE_URL را تنظیم کنید. build تصاویر ثابت مورد استفاده رکوردها را هم در dist/assets/images کپی می‌کند.

## ادمین و کد محلی

ادمین فعال 09929972390 در دیتابیس محلی موجود است. OTP_PROVIDER=mock کد تصادفی واقعی تولید می‌کند و در لاگ [MOCK SMS] و جدول otpVerifications قابل مشاهده است. کد ثابت وجود ندارد. برای ارسال واقعی، OTP_PROVIDER و MSGWAY_API_KEY را با تنظیمات سرویس پیامک خود پر کنید؛ کلید نباید داخل سورس قرار گیرد.

## قراردادهای افزوده

- POST /api/v1/catalog/:token/access: فیلد shoes با همان DTO کفش اضافه شده است. فقط DIRECT مجاز است؛ OTP تا پیاده‌سازی احراز هویت خریدار مسدود است.
- POST /api/v1/inquiries: مطابق docs/api/inquiry-endpoint-spec.md، پاسخ envelope استاندارد پروژه و id رشته‌ای؛ خطاهای 400 و 429. محدودیت ۵ درخواست در دقیقه برای هر IP.
- GET /api/v1/inquiries: فقط Bearer ادمین، آرایه ۱۰۰ درخواست آخر. مهاجرت 000009 الزامی است.

## محدودیت‌های باقی‌مانده

ورود پیامکی خریدار هنوز API ندارد؛ UI اجازه احراز هویت نمایشی با 12345 نمی‌دهد. دسترسی مشتری با همان POST/PUT /links و فیلد isDirectAccess=true ذخیره می‌شود. برای هر مشتری حداکثر یک رکورد از این نوع وجود دارد؛ از فهرست لینک‌های اشتراکی جداست و از پنل مشتری قابل مشاهده است. مهاجرت 000010 الزامی است. وضعیت انتشار کفش و فعال/غیرفعال بودن دسته نیز در مدل سرور وجود ندارد. فهرست استعلام از صفحه مشتریان حذف شده ولی API ثبت آن برقرار است.

## نتایج تست عملی

CRUD دسته/کفش/مشتری/لینک، آپلود تصویر، انتخاب کاور و حذف رسانه، ابطال و فعال‌سازی لینک، pagination، ثبت استعلام از فرم و نمایش در پنل تأیید شدند. تست‌های منفی: 401 بدون توکن، 400 کد غلط/ورودی نامعتبر/محصول ناموجود، 403 لینک باطل یا OTP، 404 توکن نامعتبر، 410 انقضا و 429 نرخ استعلام تأیید شدند. رکوردهای موقت تست CRUD پاک شدند.

Chrome: ظاهر دسکتاپ و موبایل بررسی شد، در عرض 390 overflow وجود نداشت؛ بارگذاری نهایی پنل بدون خطا/هشدار کنسول و درخواست‌های عادی با 200/304 انجام شد. اعداد load صرفاً محلی‌اند و جایگزین ممیزی production نیستند. build لندینگ همچنان درباره chunk بزرگ مدل سه‌بعدی هشدار می‌دهد.
