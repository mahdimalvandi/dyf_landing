# چک‌لیست اقلام مورد نیاز برای شروع پروژه و نقشه راه پیاده‌سازی
**نسخه سند:** ۱.۰  
**پروژه:** DYF Private Catalog Backend  
**هدف:** تعیین دقیق کلیه موضوعاتی که قبل و حین شروع کدنویسی باید تثبیت شوند تا هیچ ابهامی برای دولوپر یا ایجنت‌های هوش مصنوعی باقی نماند.

---

## ۱. فهرست موارد ضروری برای تثبیت قبل از شروع کدنویسی

برای راه‌اندازی زیرساخت بک‌اند پروژه، موارد زیر در این چک‌لیست دسته‌بندی شده‌اند:

### ۱.۱. زیرساخت پایگاه داده و محیط اجرا (Database & Environment)
- [ ] **تعیین نوع دسترسی به پایگاه‌داده در محیط توسعه:**
  - آیا PostgreSQL به صورت داکر کامپوز (`docker-compose.yml`) اجرا می‌شود یا سرویس لوکال نصب شده است؟
- [ ] **متغیرهای محیطی استاندارد (`.env`):**
  - پورت سرور (پیش‌فرض پیشنهادی: `8080`)
  - آدرس اتصال به پایگاه‌داده (`DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`)
  - کلید محرمانه امضای JWT یا سشن‌ها (`JWT_SECRET`)
  - محیط اجرا (`APP_ENV=development` یا `production`)

### ۱.۲. استراتژی ذخیره‌سازی فایل‌های چندرسانه‌ای (Media Storage)
- [ ] **محل ذخیره فایل‌ها در فاز اول (توسعه و تست):**
  - آیا تصاویر و ویدیوهای آپلودشده فعلاً در دایرکتوری لوکال سرور (`./uploads/...`) ذخیره و به عنوان Static File با فریمورک Fiber سرو شوند؟
  - آیا ساختار برای اتصال به آبجکت‌استوریج S3/MinIO آماده‌سازی شود؟
- [ ] **محدودیت‌ها و فرمت‌های مجاز:**
  - تصاویر: `image/jpeg`, `image/png`, `image/webp` (حداکثر ۱۰ مگابایت)
  - ویدیوها: `video/mp4`, `video/webm` (حداکثر ۱۰۰ مگابایت)

### ۱.۳. سرویس پیامک و احراز هویت یک‌بارمصرف (OTP Service)
- [ ] **نحوه عملکرد OTP در فاز توسعه:**
  - تعریف حالت Mock/Debug: در محیط لوکال، کد ثابت (مثلاً `12345`) پذیرفته شود و متن پیامک در کنسول لاگ شود.
  - مشخص کردن ارائه‌دهنده وب‌سرویس پیامکی در پروداکشن (Kavenegar، FarazSMS، یا SMS.ir).
- [ ] **قوانین امنیتی و محدودیت نرخ (Rate Limiting):**
  - محدودیت درخواست مجدد کد (حداقل فاصله ۱۲۰ ثانیه بین دو ارسال).
  - حداکثر ۵ بار تلاش اشتباه برای هر کد پیش از باطل شدن آن.

### ۱.۴. قراردادهای API و هماهنگی با فرانت‌اند موجود
- [ ] **مسیر پیشوند APIها:**
  - مسیرهای عمومی/کاتالوگ: `/api/v1/catalog/...`
  - مسیرهای احراز هویت: `/api/v1/auth/...`
  - مسیرهای پنل مدیریت: `/api/v1/admin/...`
- [ ] **اتصال به فرانت‌اند فعلی:**
  - فرانت‌اند فعلی با جاوااسکریپت خالص و LocalStorage کار می‌کند. بک‌اند باید به گونه‌ای طراحی شود که توابع fetch فرانت‌اند بدون دستکاری ساختار UI، به راحتی به اندپوینت‌های بک‌اند متصل شوند.

## ۲. فهرست کامل اندپوینت‌های سامانه (API Endpoints Roadmap)

### ۲.۱. ماژول احراز هویت (`/api/v1/auth`)
| متد | مسیر | شرح عملکرد | دسترسی |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/auth/admin/send-otp` | ارسال کد تایید ورود به شماره همراه مدیر | عمومی |
| `POST` | `/api/v1/auth/admin/verify-otp` | اعتبارسنجی کد و صدور توکن دسترسی مدیر (JWT) | عمومی |
| `POST` | `/api/v1/auth/customer/send-otp` | ارسال کد تایید برای ورود به کاتالوگ VIP | عمومی |
| `POST` | `/api/v1/auth/customer/verify-otp` | اعتبارسنجی کد و صدور توکن سشن کاتالوگ | عمومی |

### ۲.۲. ماژول مدیریت دسته‌بندی‌ها (`/api/v1/admin/categories`)
| متد | مسیر | شرح عملکرد | دسترسی |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/admin/categories` | لیست کلیه لاین‌ها و دسته‌بندی‌ها با تعداد مدل‌های منتسب | ادمین |
| `POST` | `/api/v1/admin/categories` | ایجاد لاین/دسته‌بندی جدید | ادمین |
| `GET` | `/api/v1/admin/categories/:id` | دریافت جزئیات یک دسته‌بندی | ادمین |
| `PUT` | `/api/v1/admin/categories/:id` | ویرایش عنوان، اسلاگ و توضیحات دسته‌بندی | ادمین |
| `DELETE`| `/api/v1/admin/categories/:id` | حذف دسته‌بندی با جداسازی ایمن انتساب مدل‌ها | ادمین |

### ۲.۳. ماژول مدیریت مدل‌های کفش (`/api/v1/admin/shoes`)
| متد | مسیر | شرح عملکرد | دسترسی |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/admin/shoes` | لیست مدل‌ها همراه با فیلتر دسته‌بندی، جستجوی زنده عنوان/کد و صفحه‌بندی | ادمین |
| `POST` | `/api/v1/admin/shoes` | ثبت مدل جدید با انتشار مستقیم و ذخیره اطلاعات رسانه‌ای | ادمین |
| `GET` | `/api/v1/admin/shoes/:id` | دریافت شناسنامه کامل مدل کفش | ادمین |
| `PUT` | `/api/v1/admin/shoes/:id` | ویرایش عنوان، توضیحات، رنگ‌ها، سایزها و رسانه‌ها | ادمین |
| `DELETE`| `/api/v1/admin/shoes/:id` | حذف مدل کفش از سامانه | ادمین |
| `POST` | `/api/v1/admin/media/upload` | آپلود عکس/ویدیو و دریافت نشانی فایل | ادمین |

### ۲.۴. ماژول مدیریت مشتریان (`/api/v1/admin/customers`)
| متد | مسیر | شرح عملکرد | دسترسی |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/admin/customers` | لیست مشتریان و بنکداران به همراه وضعیت حساب و دسترسی | ادمین |
| `POST` | `/api/v1/admin/customers` | ثبت مشتری جدید با بررسی یکتایی شماره همراه | ادمین |
| `GET` | `/api/v1/admin/customers/:id` | دریافت پروفایل مشتری | ادمین |
| `PUT` | `/api/v1/admin/customers/:id` | ویرایش مشخصات فردی و فروشگاه | ادمین |
| `PATCH`| `/api/v1/admin/customers/:id/status` | فعال یا غیرفعال‌سازی حساب مشتری | ادمین |
| `GET` | `/api/v1/admin/customers/:id/permission` | دریافت تنظیمات دسترسی مستقیم مشتری | ادمین |
| `PUT` | `/api/v1/admin/customers/:id/permission` | ویرایش یا فعال/غیرفعال کردن دسترسی مستقیم | ادمین |

### ۲.۵. ماژول مدیریت لینک‌های اختصاصی (`/api/v1/admin/links`)
| متد | مسیر | شرح عملکرد | دسترسی |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/admin/links` | لیست کلیه لینک‌ها با فیلتر وضعیت و جستجو | ادمین |
| `POST` | `/api/v1/admin/links` | صدور لینک جدید توکن‌دار از طریق خروجی ویزارد | ادمین |
| `GET` | `/api/v1/admin/links/:id` | دریافت جزئیات و محدوده محصولات مجاز لینک | ادمین |
| `PATCH`| `/api/v1/admin/links/:id/toggle` | فعال یا غیرفعال‌سازی دستی لینک | ادمین |
| `POST` | `/api/v1/admin/links/:id/reactivate`| فعال‌سازی مجدد لینک منقضی با چرخه زمانی جدید | ادمین |
| `DELETE`| `/api/v1/admin/links/:id` | حذف کامل لینک | ادمین |

### ۲.۶. ماژول کاتالوگ خصوصی خریدار (`/api/v1/catalog`)
| متد | مسیر | شرح عملکرد | دسترسی |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/v1/catalog/validate-token` | اعتبارسنجی اولیه توکن در URL و تعیین متد ورود (مستقیم یا OTP) | عمومی با توکن |
| `POST` | `/api/v1/catalog/verify-phone` | اعتبارسنجی شماره و کد تایید برای لینک‌های تلفن‌محور | عمومی با توکن |
| `GET` | `/api/v1/catalog/session-info` | دریافت اطلاعات هویت خریدار، زمان باقی‌مانده و عنوان کاتالوگ | خریدار مجاز |
| `GET` | `/api/v1/catalog/categories` | دریافت دسته‌بندی‌هایی که حداقل یک مدل مجاز برای کاربر در آن‌ها هست | خریدار مجاز |
| `GET` | `/api/v1/catalog/shoes` | دریافت لیست مدل‌های مجاز با اعمال دقیق فرمول دسترسی و مستثنائات | خریدار مجاز |
| `GET` | `/api/v1/catalog/shoes/:id` | مشاهده شناسنامه فنی و رسانه‌های یک مدل مجاز | خریدار مجاز |

```text
  │
  ├── فاز ۲: سیستم پاسخ‌های استاندارد، مدیریت خطاها، ولیدیشن و ماژول احراز هویت OTP
  │
  ├── فاز ۳: ماژول دسته‌بندی‌ها و مدل‌های کفش با قابلیت آپلود و مدیریت گالری تصاویر

  ├── فاز ۴: ماژول مشتریان و صدور مجوزهای دسترسی مستقیم
  │
  ├── فاز ۵: ماژول صدور لینک‌های اختصاصی امن توکن‌دار، کنترل دوره‌ها و فعال‌سازی مجدد
  │
  ├── فاز ۶: موتور هسته کاتالوگ (اعمال فرمول دسترسی، تایمر سرور-محور و هندلینگ انقضا)
  │
  └── فاز ۷: تست نهایی، یکپارچه‌سازی با کدهای فرانت‌اند و مستندسازی کامل Swagger/OpenAPI
```
