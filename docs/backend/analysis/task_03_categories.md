**مسیر سند:** `docs/backend/analysis/task_03_categories.md`

## ۱. هدف تسک
پیاده‌سازی ماژول مدیریت دسته‌بندی‌های محصولات (لاین‌های کارگاه نظیر کفش رسمی، کالج و لوفر، نیم‌بوت و...) شامل:
- ثبت دسته‌بندی جدید با عنوان الزامی.
- ویرایش عنوان دسته‌بندی موجود.
- حذف دسته‌بندی بدون حذف مدل‌های کفش.
- دریافت فهرست کامل دسته‌بندی‌ها.
- مشاهده جزییات یک دسته‌بندی خاص با شناسه.

---

## ۲. طراحی پایگاه داده (Database Schema & Migration)

طبق استانداردهای مصوب معماری:
- ایجاد یک فایل مایگریشن رو به جلو (`000004_create_categories.up.sql`) و یک فایل بازگشت (`000004_create_categories.down.sql`).
- شناسه رکورد از نوع `int64` نانوثانیه (`time.Now().UnixNano()`).
- عدم درج `createdAt` و `updatedAt`.
- استفاده از نام‌گذاری با دابل‌کوتیشن و camelCase.
- صفر کامنت در فایل‌های SQL.

### ۲.۱. ساختار جدول `categories`
```sql
CREATE TABLE IF NOT EXISTS "categories" (
    "ID" BIGINT PRIMARY KEY,
    "title" VARCHAR(100) NOT NULL UNIQUE
);
```

**فیلدها:**
- `ID`: شناسه یکتا از نوع `BIGINT`.
- `title`: نام فارسی لاین محصول (حداکثر ۱۰۰ کاراکتر، الزامی، یکتا).

خانواده مسیر: `/api/v1/categories`

### ۳.۲. دریافت جزییات یک دسته‌بندی (`GET /api/v1/categories/:id`)
- **کد وضعیت:** `200 OK`
- **پارامتر مسیر:** `:id` (شناسه عددی دسته‌بندی).
- **خطاهای محتمل:**
  - `400 Bad Request` با کد `invalidCategoryID` (اگر شناسه ارسالی عدد معتبر نباشد).
  - `404 Not Found` با کد `categoryNotFound` ("دسته‌بندی مورد نظر یافت نشد").
- **خروجی:**
  ```json
  {
    "success": true,
    "statusCode": 200,
    "message": "اطلاعات دسته‌بندی با موفقیت دریافت شد",
    "data": {
      "ID": 1792754892013944001,
      "title": "کفش رسمی دست‌دوز"
    },
    "meta": null
  }
  ```

---

### ۳.۳. افزودن دسته‌بندی جدید (`POST /api/v1/categories`)
- **دسترسی:** محافظت‌شده (نیاز به توکن ادمین در هدر `Authorization: Bearer <token>`).
- **کد وضعیت:** `201 Created`
- **استراکت ورودی (Request Body):**
  ```json
  {
    "title": "بوت و نیم‌بوت"
  }
  ```
- **اعتبارسنجی:**
  - فیلد `title` الزامی است (`required`).
  - حداقل ۲ و حداکثر ۱۰۰ کاراکتر (`min=2,max=100`).
  - فاصله‌های زائد قبل و بعد خودکار Trim می‌شوند.
- **خطاهای محتمل:**
  - `400 Bad Request` با کد `validationFailed` (خالی بودن یا طول نامعتبر).
  - `409 Conflict` با کد `categoryTitleDuplicate` ("دسته‌بندی با این عنوان از قبل وجود دارد").
  - `401 Unauthorized` (عدم ارسال توکن یا توکن نامعتبر).
- **خروجی:**
  ```json
  {
    "success": true,
    "statusCode": 201,
    "message": "دسته‌بندی با موفقیت ایجاد شد",
    "data": {
      "ID": 1792754892013944003,
      "title": "بوت و نیم‌بوت"
    },
    "meta": null
  }
  ```

---

### ۳.۴. ویرایش دسته‌بندی (`PUT /api/v1/categories/:id`)
- **دسترسی:** محافظت‌شده با توکن ادمین.
- **کد وضعیت:** `200 OK`
- **پارامتر مسیر:** `:id`
- **ورودی (Request Body):**
  ```json
  {
    "title": "کفش رسمی و مجلسی"
  }
  ```
- **منطق:**
  1. بررسی وجود دسته‌بندی با شناسه ارسالی (در صورت عدم وجود: `404 Not Found`).
  2. بررسی تکراری نبودن عنوان جدید در سایر رکوردهای دسته‌بندی (در صورت تکراری بودن در رکوردی دیگر: `409 Conflict`).
  3. به‌روزرسانی عنوان دسته‌بندی.
- **خروجی:**
  ```json
  {
    "success": true,
    "statusCode": 200,
    "message": "دسته‌بندی با موفقیت ویرایش شد",
    "data": {
      "ID": 1792754892013944001,
      "title": "کفش رسمی و مجلسی"
    },
    "meta": null
  }
  ```

---

### ۳.۵. حذف دسته‌بندی (`DELETE /api/v1/categories/:id`)
- **دسترسی:** محافظت‌شده با توکن ادمین.
- **کد وضعیت:** `200 OK`
- **پارامتر مسیر:** `:id`
- **منطق:**
  1. بررسی وجود دسته‌بندی (در صورت نبود: `404 Not Found`).
  2. حذف رکورد از جدول `"categories"`.
  3. طبق قاعده محصولی: این عملیات به کفش‌ها آسیبی نمی‌زند (وقتی جدول کفش در تسک ۴ ساخته شود، فیلد `categoryID` به صورت `SET NULL` تعریف خواهد شد).
- **خروجی:**
  ```json
  {
    "success": true,
    "statusCode": 200,
    "message": "دسته‌بندی با موفقیت حذف شد",
    "data": null,
    "meta": null
  }
  ```

## ۵. سناریوهای تست و لبه‌ها (Edge Cases)

1. **ثبت دسته‌بندی با عنوان معتبر:** پاسخ ۲۱ و بازگرداندن آبجکت دسته‌بندی با ID.
2. **ثبت دسته‌بندی با عنوان خالی یا تک‌حرفی:** خطای ۴۰۰ اعتبارسنجی.
3. **ثبت دسته‌بندی با عنوان تکراری:** خطای ۴۰۹ (Conflict) با پیام فارسی مناسب.
4. **ثبت دسته‌بندی بدون توکن ادمین:** خطای ۴۰۱ (Unauthorized).
5. **دریافت فهرست:** پاسخ ۲۰۰ شامل آرایه‌ای از دسته‌بندی‌ها (یا آرایه خالی در صورت نبود رکورد).
6. **دریافت جزییات با شناسه نامعتبر یا ناموجود:** خطای ۴۰۴ یا ۴۰۰.
7. **ویرایش عنوان به یک عنوان معتبر دیگر:** پاسخ ۲۰۰ با عنوان به‌روزرسانی‌شده.
8. **ویرایش عنوان به عنوانی که قبلاً برای دسته‌ای دیگر ثبت شده:** خطای ۴۰۹ (Conflict).
9. **حذف دسته‌بندی موجود با توکن ادمین:** پاسخ ۲۰۰ و حذف از پایگاه‌داده.
10. **تلاش مجدد برای دریافت یا حذف همان رکورد حذف‌شده:** خطای ۴۰۴.

## ۶. سوالات و تصمیم‌گیری‌های اولیه جهت تأیید شما

۱. **یکتا بودن عنوان دسته‌بندی:** آیا موافقید عنوان دسته‌بندی قید `UNIQUE` داشته باشد تا جلوی ثبت دسته‌بندی تکراری هم‌نام گرفته شود؟ (پیشنهاد ما: بله، یکتا باشد).  
۲. **دسترسی به متدهای مشاهده (GET):** آیا مشاهده فهرست دسته‌بندی‌ها (`GET /api/v1/categories`) عمومی و بدون نیاز به لاگین باشد (چون در صفحه عمومی یا کاتالوگ هم ممکن است لیست لاین‌ها دیده شود)، در حالی که عملیات‌های ساخت، ویرایش و حذف (`POST`, `PUT`, `DELETE`) نیازمند لاگین ادمین باشند؟ (پیشنهاد ما: متدهای خواندن عمومی، متدهای تغییر صرفاً با توکن ادمین).  
۳. **صفحه‌بندی (Pagination):** با توجه به اینکه لاین‌های کارگاهی معمولاً کم‌تعداد هستند (کمتر از ۲۰ لاین)، آیا ترجیح می‌دهید کل لیست بدون صفحه‌بندی برگردد؟ (پیشنهاد ما: بدون صفحه‌بندی ساده).
