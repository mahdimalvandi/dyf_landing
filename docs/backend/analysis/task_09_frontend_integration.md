# اتصال فرانت‌اند به API

دامنه درخواست: اتصال و تست APIهای موجود و ورود ادمین 09929972390.

احراز هویت باید از send/verify/me/logout استفاده کند و فلگ localStorage معتبر نیست. CRUD دسته‌ها، کفش‌ها، مشتریان و لینک‌ها و آمار داشبورد مطابق docs/apiDocs متصل می‌شوند. داده‌های نمونه نباید جایگزین خطای شبکه شوند. شناسه‌های BIGINT باید بدون افت دقت پردازش شوند. آپلود از multipart استفاده می‌کند. تغییری در دیتابیس برای اتصال APIهای موجود لازم نیست.

موانع قرارداد موجود: catalog/access محصولات برنمی‌گرداند؛ OTP خریدار، دسترسی مستقیم مشتری، وضعیت کفش/دسته و inquiries هنوز API ندارند. این موارد نیازمند توسعه بک‌اند هستند و نباید موفقیت جعلی نمایش دهند.

تست‌ها: build و تست Go/JS، احراز هویت صحیح و غلط، CRUD، pagination، آپلود، لینک و کنترل دسترسی، مرورگر Chrome در دسکتاپ/موبایل، کنسول و شبکه. OTP محلی با provider موجود mock و رکورد واقعی دیتابیس تست می‌شود؛ کد ثابت یا bypass اضافه نمی‌شود.

## تکمیل دامنه در اجرا

- پاسخ catalog/access اکنون shoes را فقط از shoeIDs لینک برمی‌گرداند و برای روش OTP بدون احراز هویت دسترسی نمی‌دهد.
- جدول inquiries در migration 000009 با ID نانوثانیه‌ای و ستون‌های store_name، city_market، phone_number، line_preference، source، status اضافه شد. POST عمومی با محدودیت ۵ درخواست در دقیقه و GET ادمین (۱۰۰ مورد آخر) پیاده شد؛ درخواست‌ها در صفحه مشتریان نمایش داده می‌شوند.
- نام مدیر و تاریخ داشبورد دیگر ثابت نیستند. تایمر از زمان سرور استفاده می‌کند و دسترسی هر ۳۰ ثانیه دوباره بررسی می‌شود.
- بازپخش هم‌زمان OTP با مصرف شرطی رکورد مسدود و verify به ۱۰ تلاش در دقیقه محدود شد.

## اصلاحات بازخورد کاربر

- مشاهده مدل‌های دسته فیلتر نام دسته را به ShoesView منتقل می‌کند؛ ورود معمول از منوی مدل‌ها فیلتر را بازنشانی می‌کند.
- بخش درخواست‌های همکاری از صفحه مشتریان حذف شد.
- دسترسی مشتری از همان API لینک با isDirectAccess=true استفاده می‌کند؛ migration 000010 یک فیلد و ایندکس یکتای شرطی برای یک دسترسی در هر مشتری اضافه می‌کند. ایجاد/ویرایش/ابطال/فعال‌سازی با API موجود انجام می‌شود و رکورد از لیست لینک‌های اشتراکی جدا نمایش داده می‌شود.
- عدد و واحد ورودی زمان جابه‌جا شدند. فرمت مشترک زمان، 4320m را به «۳ روز» تبدیل می‌کند.
- تست مرورگر شامل فیلتر دسته، ماندگاری تنظیمات مشتری بعد از رفرش، عدم ایجاد رکورد تکراری، ابطال و فعال‌سازی، باز کردن کاتالوگ محدود به محصول انتخابی و نبود overflow در موبایل بود.
